# 人物视角真实买家秀提示词（persona-ugc-i2i-prompts）

## 这个 skill 做什么

输入：一批卡套挂件产品实拍图（卡套 + 弹簧挂绳、星环、铃铛等配件，浅色摄影台背景）。
输出：桌面上一个 txt 文件，内含大量中文图生图提示词（默认每图 30 条、每条 ≥400 字），供 GPT-Image-2 把产品原图变成"像真实买家随手拍的"生活场景照。

核心难题不是写出一条好提示词，而是**几十条、将来上千条放在一起时不能有"同一张照片换背景"的雷同感**。本 skill 的解法是人物法：先虚构具体的人和她的生活，再从她的视角自然长出照片——细节之间有因果关联，而不是从维度矩阵里随机拼贴。配套一个跨批次台账做短期冷却去重。

## 不可妥协的红线（贯穿一切环节）

产品本体必须与原图完全一致：卡套的形状、颜色、图案，印在上面的人像照片、版式和所有文字，配件的种类/数量/颜色，以及配件与卡套之间的连接孔位和连接方式——一律不得增删改。唯一允许的变化：挂绳、铃铛、星环等**自然下垂的部分**可以随新的摆放姿态做符合重力逻辑的垂落调整——但这种调整**永不包括移动连接孔位**：配件永远从原图同一个挖孔引出。实测翻车全部集中在悬挂姿态（连接点漂移、卡套变形、卡面被重新排版重绘），方法论第五节为此单设了悬挂姿态配额（≤1/5）、孔位锚定句和卡面朝向锚定句要求；且全 skill 遵守"位置结构只做正面描述"原则——提示词里点名否定某个错误位置（如某条边），图像模型反而会把它画出来。同时注意保真锁的是产品"身份"（结构/图案/文字/版式/配件/孔位），**光影不在锁定范围**：每条保真块都带光影融合句，要求产品接受新场景的现场光并投下自然影子，否则会像抠图 P 上去的贴纸。

画幅是统一硬规格：**所有提示词一律 3:4 竖幅**，写死在每条保真块末句，不作为随机要素。

第二条红线是画面下限：这些图要经得起"发到社交媒体有人愿意看"的检验。真实感来自随手感和生活痕迹，不来自昏暗、脏乱、无聊——又暗又乱又没有拍照动机的场景即使再"真实"也是废片（判据和昏暗场景配额见 prompt-craft.md 第一、三节）。

另外注意区分两件事：产品上**印刷的人像**是产品的一部分，必须原样保留；而**场景里的真人**绝不允许露脸（手、手腕、腿等身体局部可以入镜且值得鼓励，见方法论）。

## 主流程

### 第 0 步：确认输入

向用户拿到图片路径清单（用户可能给文件夹或具体文件）。默认每图 30 条、每条 ≥400 字、中文；用户如有指定以用户为准。

### 第 1 步：读台账，生成回避清单

台账位于项目根目录 `提示词台账/ledger.txt`（不存在则本批跳过回避、批末创建）。台账每行是一条历史提示词的粗粒度指纹：

```
批次日期 | 产品 | 人物一句话 | 场景地点 | 核心道具 | 动作/产品状态 | 时段季节
```

回避规则的设计意图：用户的 SKU 很多但产品形态相似，**场景是可以跨期复用的**，要防的只是短期视觉疲劳。所以：

- 只取**最近 2 个批次**的指纹作为"本批回避区"——这些「地点+道具+动作」组合本批不要再出。
- 更早的历史不禁用，但扫一眼全史：若某组合出现 ≥5 次，列入"高频提示"让子代理少用。
- 去重的单位是**组合**而非元素。奶茶可以永远出现，"宿舍床头+奶茶+拆快递"这个组合才是要冷却的对象。

把回避区和高频提示压缩成一段几百字的摘要，随任务下发给每个子代理。

### 第 2 步：为每张图分配人群倾向池

人物有一条全局设定：**一律是 20–25 岁女性**（产品用户 100% 是这个人群），所有场景从她们的视角策划。因此分池的差异维度是职业阶段、居住形态、爱好圈层、城市——不是性别年龄。

多个子代理独立虚构人物时会不约而同撞向同一类人（大学生宿舍追星女孩）。所以扇出前先为每张图分配一个**互不重叠的人群倾向池**，例如：图 A 偏「实习/初入职场、租房」、图 B 偏「在校学生、宿舍/教室」、图 C 偏「自由职业/在家、居家场景为主」、图 D 偏「爱出门的、通勤/逛街/旅行场景为主」。池只是倾向和出发点，子代理在池内自由发挥，也允许少量越池——目的是让批内整体分布散开，不是做硬隔离。分池时结合回避清单：上批哪类人多，这批就往别处偏。

另一条全局配比：**每批约 20% 的条目含猫咪元素**（品种不限，出现必须自然——从人物小传里长出来，写法见方法论第二节"猫咪时刻"）。这是每图各自达标的比例，子代理自己保证；猫算核心道具入指纹，所以"猫+地点+动作"的组合同样吃台账冷却，分池时若上两批猫场景扎堆在某类地点，就提示子代理往别处挪。

### 第 3 步：扇出子代理（每图一个）

读 [references/subagent-task.md](references/subagent-task.md)，按模板为每张图填好占位符（图片路径、条数、倾向池、回避摘要、当前真实日期与季节、产出目录用当前会话的 scratchpad、本 skill 的绝对路径），**同一轮里并行启动所有子代理**。一图一个子代理的原因：避免长上下文里前面写的提示词把后面的带向趋同，也避免跨产品串味。

当前真实日期很重要：季节、天气、开学季/毕业季/节假日这些时间锚点要真实带入，它们让不同月份的批次天然长得不一样，是免费的跨批次去重器。

### 第 4 步：跨产品查重，再合并输出到桌面

子代理只能保证自己批内不撞车，看不见彼此。所以合并前主代理要把所有产品的指纹文件放在一起比对一遍：不同产品的两条若在「地点+核心道具」层面高度重合（例如都是"竹凉席+西瓜+落地扇的午后"），用 SendMessage 让其中一个子代理重写它那条（告知撞车内容，让它换一个该人物的其他生活时刻），收到修订后再合并。同名元素不算撞车，组合才算。

确认无撞车后，把各自产出的 `<产品名>.txt` 合并为一个文件：

`~/Desktop/卡套真实场景提示词_YYYYMMDD_批次N.txt`（同日多批则 N 递增）

格式：按产品分组，组标题一行【<产品名>场景图】（产品名取卡套上印的名字，如【侯明昊场景图】）；组内每条提示词占两部分——第一行小标题（【玛德琳台】这种 3–8 字场景短题，子代理已写好），下一行组内序号加正文。条与条之间空一行，组与组之间空两行。示例：

```
【侯明昊场景图】

【玛德琳台】
1. 把图中这只印有明星照片的浅绿色驾照风格卡套……

【宿舍床头】
2. 把图中这只……
```

### 第 5 步：追加台账

把每个子代理产出的指纹文件（`<产品名>.fingerprints.txt`）追加进 `提示词台账/ledger.txt`，批次头部加一行注释（`# 批次 YYYY-MM-DD-N | 图片文件名 | 总条数`）。台账在项目里跟 git 走，不要放 scratchpad。

### 第 6 步：向用户汇报

报告：输出文件路径、总条数、各产品条数、本批用掉的人物概况（一句话级别）、台账更新情况。如有子代理失败，如实说明并单独补跑。

## 质量责任划分

- 子代理负责：识别产品名、单条质量（方法论见 [references/prompt-craft.md](references/prompt-craft.md)，模板里已指路）、批内自查去重。
- 主代理负责：分池防批内趋同、回避清单防跨批趋同、合并格式、台账维护。
- 合并前主代理抽查每个产品文件：头两条看字数是否达标、保真约束块是否完整（配件逐件点名、孔位正面锚定、含"排版"二字、光影融合句、末句 3:4 竖幅）、每条是否带小标题、是否有真人露脸描述；再全文粗扫四件事——悬挂类条目是否都同时带孔位锚定句和卡面朝向锚定句且占比 ≤1/5，有没有"不要挂在""长侧边"这类点名错误位置的负向表述（有即不合格），昏暗/无聊场景是否超标（每档最多一两条昏暗），含猫条目是否约 20% 且互动低风险、人物是否全为 20–25 岁女性。发现整档跑偏就让该子代理重做，不要自己动手逐条修补。

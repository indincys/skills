# 小红书爆款标题（xhs-baokuan-titles）

## 这个 skill 做什么

**输入**：主力产品是 **NFC 音乐证件卡套挂件**——可当书包挂件/钥匙扣，卡位能放证件卡；外观按明星应援色定制、带明星元素，所以一人一款不撞款；内置 NFC 芯片，手机碰一下可跳转音乐歌单 / 追剧 App / 游戏 App / 微博超话，**单次只能录一种功能，但可随时重录切换**。用户按每天数篇的节奏长期发小红书，明星和卡套款式有上百组。

**输出**：一批可直接粘贴使用的标题，每条带「钩子类型 / 目标人群 / 命中的产品关键词 / 推荐型或搜索型」标注（方便挑选和复盘数据），合并写成桌面 txt，并在对话里完整贴一遍。

**不做跨批次去重**：数据好的标题本来就该反复用，只要不是天天重复同一条就没问题。所以本 skill 不维护台账、不设冷却期——去重只管**同一批之内**不要条条同构（见下「批内分布」）。

**为什么这件事值得单独做**：标题是整条笔记唯一决定"点不点进来"的东西。首图和标题定生死，正文再好，没人点开就等于没发。而标题只有十几个字，可操作空间极小——同样的产品、同样的卖点，写法差一点，点击率差几倍。

**四种失败模式，按实际发生频率排序**（本 skill 一多半篇幅都在防它们）：

1. **关联性断裂**——标题没写清是什么东西、也没有圈层信号，读者拼不出这跟自己有关（"食堂阿姨都问我这个是什么"）。这是实战中最常犯、也最隐蔽的一种，因为它读起来像是有悬念的。
2. **浮夸**——细节的量级不对，看着有料实际像编的（"挂了87天""同事排队来碰"）。
3. **普通**——只有功能事实，换成同品类别的牌子也成立（"原来一个卡套能塞进三样东西"）。
4. **形容词流水线／产品介绍腔**——"这个宝藏挂件真的太好用了""NFC音乐卡套挂件一碰就播歌"。这两种不是标题，是货架标签。

如果哪天要给别的产品出标题，方法论整套照用，只是把「素材库」里的产品专属锚点换掉即可。

## 地基：一条爆款标题的三层解剖

一条能爆的标题同时干了三件事，缺一件就掉一个量级：

| 层 | 它负责什么 | 落地成什么 |
|---|---|---|
| **钩子** | 让手指停下来 | 一个钩子类型（社交证明/反常识/反差/悬念…，12 类见 toolkit） |
| **具体锚点** | 让人知道这跟自己有关，并且相信是真事 | **圈层/身份词** ＋ **实物/场景词**，再加一个数字、人物或原话 |
| **信息缺口** | 让人必须点进去 | 读完标题，心里冒出一个只能点进去才能解决的疑问 |

三层的关系：钩子是形式，锚点是关联性和可信度，缺口是动机。**"39块把本命歌单挂在了书包上"** ——数字锚（39块）＋圈层词（本命）＋实物词（歌单、书包）＋缺口（歌单怎么会挂在书包上）。三层齐了。

**锚点这一层是最容易做塌的**：它要同时承担"这跟我有关"和"这是真事"两件事，所以圈层词和实物词必须都在，数字还得在日常尺度内。做塌的两种样子就是浮夸和普通，见下面第 ③ 道测试和「另一个死法」。

**记住这条总纲：标题不介绍产品，标题掐出一个未完成的瞬间。**
产品是什么、好在哪，是正文和首图的活。标题只负责制造一个"欠着答案"的瞬间。

## 四道一票否决的测试

每条标题写完先过这四道，不过就整条重写，不要修补。它们比后面的质检清单更根本，其中**第一道最重要，也是最容易做错的一道**。

### ① 关联性测试（最重要）

标题里必须能同时读到两样东西：

- **A｜圈层或身份信号**：追星、本命、我家哥哥、我姐、墙头、同担、蹲、打榜、超话、应援色、冷门家、老粉；或明确人群词（高中生、住宿党、打工人、毕业生）。
- **B｜实物或场景锚**：挂件、卡套、书包、工牌、校园卡、钥匙、手机、歌单、超话打卡、追剧、网课、宿舍、地铁、演唱会。

两样凑齐，读者扫过 0.3 秒就能拼出「这是给追星的人用的某个随身小物」，于是判断"这跟我有关"，然后才会停。缺了 A，圈层读者不认领；缺了 B，读者根本不知道你在讲什么东西。

- ✗ 「食堂阿姨都问我这个是什么」→ 食堂阿姨在圈外，"这个"不是实物锚。读者联想不到明星周边，划走。
- ✗ 「挂了87天，颜色一点没掉过」→ 有实物暗示但零圈层信号，读起来像质检报告。
- ✓ 「同桌天天来碰我书包上的NFC挂件」→ 同桌（校园身份）＋书包/NFC挂件（实物＋关键词）。
- ✓ 「一碰进超话，每天打卡少点8下」→ 超话/打卡（圈层＋场景双命中）。

**这里有一个反直觉但必须记住的点：缺口不是靠藏产品制造的，是靠藏原因和结果制造的。**
产品和场景要写明白，"为什么会这样""后来怎么了"才是留白的地方。把产品藏起来确实能造出悬念，但那种悬念是无指向的——读者不知道这条内容属于哪个话题，也就无从判断值不值得点。一批标题如果大面积出现"这个""它""那个小东西"当主语，说明整批已经跑偏了。

### ② 缺口测试

读完标题，读者心里有没有一个**具体的**疑问？把那个疑问用一句话说出来，说不出来就是答案给完了。产品介绍句必然过不了这一道——它把什么都说完了。

- ✗ 「NFC音乐卡套挂件，一碰就播歌超方便」→ 说完了，且是货架标签。
- ✓ 「我的工牌卡套会自己放歌（离谱」→ 疑问是"卡套怎么可能自己放歌"。

### ③ 可信度测试

这件事在真实生活里会这样发生吗？**浮夸和形容词流水线一样致命，只是伪装得更好**——它看起来有细节，但细节的量级不对，读者一眼就觉得是编的。

- **数字要取日常尺度**：问了三次、买过五个、少点八下、看了十分钟 ✓；挂了87天、录了11次 ✗。精确到刺眼的数字不显得真实，显得像编的。
- **旁人反应要在常理内**：转过来问、拿走看了十分钟、说她也要一个 ✓；排队来碰、全班沸腾、所有人都在问 ✗。
- **不写质检腔**：颜色没掉、用半年没坏、做工扎实——这是详情页的活。标题写耐用度，读者收到的信号是"这人在推销"。

### ④ 顺口测试

念出来。中文标题读不顺就没人看第二遍——信息流里读者不会为一个别扭的句子停留。

- ✗ 「后座这周第三次伸手来碰我书包」→ "伸手来碰"是书面拼装，读起来卡。
- ✓ 「同桌天天来碰我书包上的挂件」→ 一口气读完。

## 另一个死法：普通

一批标题有两种死法，**浮夸和普通**，而且它们会同时出现——一边使劲编夸张细节，一边剩下的条目平得像说明书。上面第 ③ 道管浮夸，普通得单独判：

**判定方法**：把这条标题里的产品换成同品类任意一个牌子，它还成立吗？成立就是普通稿。
- ✗ 「原来一个卡套能塞进三样东西」→ 任何一个卡套都能这么说，没有圈层、没有情绪、没有旁人，只剩一个功能事实。
- ✓ 「原来证件卡套还能藏一个歌单」→ "歌单"把它锁定成本品，而且"藏"字带了情绪。

**普通稿的成因**：只写了功能事实，没带上人。修法是往里加人——加一个身份词、一个旁人反应、或一个情绪落点，三样加一样就活。

## 推荐流和搜索流要分开配比

小红书是**推荐＋搜索双引擎**，两种流量吃的是完全不同的标题，一批标题里必须都有：

- **推荐型（占约 70%）**：靠钩子抢点击。信息缺口大、情绪强、可以不出现品类词。上面两个测试主要考它。
- **搜索型（占约 30%）**：靠关键词吃长尾搜索。**关键词必须前置**，句子可以平一点，但仍要带一个钩子或利益点，不能写成纯关键词堆砌。
  本品的高价值搜索词：NFC挂件、书包挂件、证件卡套、钥匙扣、应援周边、生日礼物、毕业礼物、闺蜜礼物、追星好物、学生党。
  - ✓ 「毕业礼物就买这个，我们班人手一个不同色」（关键词前置＋数量锚）
  - ✓ 「书包挂件推荐：会放歌的那种，同学全在问」（关键词前置＋社交证明）
  - ✗ 「NFC挂件书包挂件证件卡套推荐」（纯堆词，平台和人都不喜欢）

出稿时在每条后面标注是哪一型，这样用户能按投放目的挑，也能回头看哪一型数据更好。

## 关键词要埋进每一条，包括推荐型

上面那个 70/30 说的是**关键词前置**这件事只有搜索型需要，但**关键词出现**这件事 50 条都需要。原因是小红书的搜索是**分词匹配**：标题里有"NFC"和"挂件"两个词元，就能被「NFC挂件」这个搜索词命中，不需要它们连在一起成词。

所以每条标题都至少携带一个产品关键词词元。产品关键词池（可拆开分词，不必共现）：

**NFC ／ 音乐 ／ 挂件 ／ 卡套 ／ 证件卡套 ／ 书包挂件 ／ 钥匙扣 ／ 应援色**
（组合起来自然覆盖：NFC挂件、NFC音乐、音乐挂件、NFC音乐挂件、NFC卡套、证件卡套挂件…）

**最省力的埋法：把已经在句子里的泛称词升级成关键词的完整形态，而不是新增成分。**这是零成本的——句子长度和语气都不变：

| 原来写的 | 升级成 | 多吃到的搜索词 |
|---|---|---|
| 追星挂件 | NFC挂件 | NFC、NFC挂件 |
| 那个挂件 | 音乐挂件 / NFC音乐挂件 | 音乐、音乐挂件、NFC音乐 |
| 卡套 | 证件卡套 / NFC卡套 | 证件卡套、NFC卡套 |
| 就有歌 | 就有音乐 | 音乐 |
| 碰下书包 | 碰下书包挂件 | 书包挂件 |

**三条上限，防止埋成堆词**：

1. **一条最多两个关键词成分**，且只能占名词位。关键词是句子里的东西，不是句子的目的。
2. **埋完必须重过顺口测试**。「追星NFC音乐挂件不是买来看的」这种就是堆过头了——读者读不顺，搜索权重也换不回来。宁可这条只带"挂件"，把 NFC 让给下一条。
3. **关键词不能挤掉圈层词**。关联性是点击率，关键词是曝光量，点击率优先——一条标题如果为了塞 NFC 把"本命"挤掉了，那是赔本。

**批次层面看覆盖**：50 条这种批量，出稿后横向数一遍每个关键词各覆盖了多少条，让主关键词（NFC、挂件、卡套、音乐）都有一定条数分布，不要 40 条全押在"挂件"上——那样其他长尾词一条都吃不到。

## 三条红线

**红线一：形容词流水线是唯一能让整批标题全废的东西。**
"宝藏、绝绝子、超好用、太爱了、神仙、必买、yyds、爱惨了、无脑冲" 这类评价词，信息量为零，读者已经免疫。**评价词一律换成动作、数字或旁人反应**——不说"超好用"，说"同桌问了三次"；不说"神仙配色"，说"全世界只有我这一个"。黑名单全表见 toolkit。

**红线二：功能如实，不用违禁词。**
NFC 只能写成"碰一下跳转某一个 App / 可以随时重录换成别的"，**绝不写"四合一同时能用""一碰全都能"**——这是硬伤，会招来差评和退货。同时不用绝对化违禁词（最/第一/绝对/顶级/独家/永久/国家级…全表见 toolkit），不编销量榜单数据。

**红线三：明星真名和应援色不自行编造。**
应援色、专属元素、超话名只认用户提供的资料，没有提供就**不要猜色号**。更重要的是：**标题里直接出现明星真名有风险**（艺人周边涉及肖像权，平台对这类带货标题也管得紧），所以默认用圈层代称——「本命 / 我家哥哥 / 我姐 / 我墙头 / 应援色」——让粉丝自己代入，同时把真名留给评论区自然发酵。用户明确要求真名进标题时才写，并在汇报里提示一次风险。

## 主流程

### 第 0 步：确认这批要什么

问清（或从用户话里判断）：**出几条**、**给谁**（哪个明星/卡套，或哪类人群）、**有没有指定素材**（一张图、一条已写好的正文、一个具体场景）。用户没说数量就默认 **20 条**。

两种进稿方式，做法一样，只是第 1 步的取材不同：
- **从零批量**：用户说"来 20 条标题""这个明星出 10 条"。
- **给已有素材配标题**：用户甩来一张图或一段正文要点，说"给这篇配几个标题"。此时先提取素材里已有的具体锚点（图里的场景、正文里的数字和对话），标题必须和素材呼应；并且**不要重复首图已经说清的信息**——首图已经把产品拍清楚了，标题就别再报品类，去补首图给不了的那层（旁人反应、疑问、后果）。

### 第 1 步：先定这批要卖哪几个"瞬间"

标题卖的不是卖点，是卖点变成生活里的那一秒。先从下面挑本批主打的 2–3 个瞬间，后面所有标题都从这几个瞬间里长出来：

| 卖点 | 掐成什么瞬间 |
|---|---|
| NFC 一碰跳歌单 | 手机往书包上一贴，歌响了，旁边人回头 |
| 应援色一人一款 | 一堆挂件里只有我这个颜色，别人问这是谁 |
| 卡套＋钥匙扣＋挂件 | 出门一串带走，包里少了两样东西 |
| 可随时重录 | 这周录歌单，考试周换网课，追剧时换剧集 |
| 适合送礼 | 拆礼物的人当场愣住/眼睛红了 |

写不出瞬间的卖点，就先别放进这批标题。

### 第 2 步：先铺矩阵，再动笔

**这一步不能省，它是防止一批标题长得一模一样的唯一手段。** 直接一条条硬写，写到第 6 条就会开始自我抄袭——前面写过的句式会变成惯性，越往后越像。

先列一张表（内部草稿即可，不必给用户看），一行一条，填四列：**钩子类型 / 目标人群 / 场景或瞬间 / 推荐型还是搜索型**。填的时候就检查分布是否达标（见下「批内分布」）。表填完再逐行写标题。

### 第 3 步：逐条出稿——先写长的具体句，再压到 18 字

这是本 skill 最实用的一个手法，务必照做：

1. **先写一句不限长度的具体话**，把锚点写足：谁、在哪、做了什么、别人什么反应、几次、多少钱。
   例："我同桌今天第三次转过来问我书包上那个挂件是在哪买的"
2. **再往下压到 12–18 字**，压的时候只删信息，不加评价词。
   例：「同桌问了我三次这个挂件哪买的」

为什么要这样：**一上手就想短句，大脑会去抓形容词填空**（"超好用的宝藏挂件"），因为形容词最省事。先写长句能强迫自己先有具体事实，压缩时留下的就都是硬信息。

**压缩阶段有一个坑，专门在这里提醒**：为了省字，最容易被砍掉的恰恰是"挂件""书包""本命"这些看起来啰嗦的词，砍完句子确实短了，但关联性一起没了——「同桌天天来碰我书包上的挂件」压成「同桌天天来碰我书包」就废了。压缩时**圈层词和实物词是不能动的骨头**，要砍就砍修饰、砍连接词、砍解释。

长度和符号规则：**正文标题 12–18 字最佳，超过 20 字会被截断**；emoji **最多 1 个**且要有实义（🥹 表情绪、👀 表悬念），不要装饰性堆叠；括号半开不收口（"（早买啊"）是有效的留白手法，别用滥。

### 第 4 步：逐条过质检

按下面「质检清单」十条逐条过。不过的当场按对应改法改掉，改不动就丢掉重写一条——**标题很便宜，别在一条烂标题上抢救**。

### 第 5 步：输出

写 `~/Desktop/小红书标题_YYYYMMDD_批次N.txt`（同日多批 N 递增），同时在对话里完整贴一遍（标题短，用户要当场挑）。文件结构：

```
【推荐型】
1. <标题>
   钩子：社交证明 ｜ 人群：高中生 ｜ 关键词：NFC挂件 ｜ 缺口：为什么天天来碰

【搜索型】
36. <标题>
    关键词：毕业礼物＋NFC卡套 ｜ 钩子：稀缺 ｜ 人群：毕业生

【关键词覆盖】（横向数一遍，看长尾有没有押偏）
NFC xx条 ｜ 挂件 xx条 ｜ 卡套/证件卡套 xx条 ｜ 音乐 xx条 ｜ 书包挂件 xx条 ｜ 应援色 xx条

【速取区】（只有标题，方便直接复制）

```

末尾那个「速取区」很重要——用户实际发布时要的是一列干净的纯标题，不想在标注里找。

### 第 6 步：汇报

报：文件路径、总条数、推荐型/搜索型各多少、覆盖了哪些钩子类型和人群、**各产品关键词覆盖了多少条**、批内分布是否达标；以及需要用户确认的东西（明星应援色资料缺失、用户要求真名进标题时的风险提示）。

## 质检清单（每条都要过，附改法）

前四条对应四道一票否决测试，**不过就整条重写，不修补**：

1. **关联性齐** —— 圈层/身份词和实物/场景词都在。缺圈层：加一个（本命/追星/同担/应援色/高中生…）。缺实物：把"这个/它"换成具体物件（挂件/卡套/书包/工牌/歌单）。
2. **缺口在** —— 不过：把句子后半段的答案砍掉，或改成旁人视角的疑问。
3. **可信** —— 数字回到日常尺度；旁人反应回到常理；删掉耐用度和做工描述。
4. **顺口** —— 念一遍，卡在哪就把那个词换成口语词。

剩下六条按需修改即可：

5. **带产品关键词** —— 至少一个词元（NFC/音乐/挂件/卡套/证件卡套/书包挂件/钥匙扣/应援色），最多两个，只占名词位。没有：把句子里的泛称词升级成关键词形态，不要新增成分。
6. **不普通** —— 换成同品类别的牌子还成立的，加一个身份词/旁人反应/情绪落点。
6. **长度 12–18 字，emoji ≤1** —— 超长：删解释性成分，保留最硬的那个锚点。
7. **无形容词流水线词** —— 有：把评价词换成动作、数字或旁人反应。
8. **钩子命中 2–3 个，不超过 3 个** —— 堆多了每个都糊，删到最强的两个。
9. **与本批其他条不同构** ——「钩子＋句式骨架」不与同批任一条相同。犯了就换钩子家族重写，不要只换词（换词躲不过读者"这条我刚看过"的感觉）。
10. **合规** —— 无绝对化违禁词；NFC 写成单次一种、可重录；明星真名和应援色按红线三。

## 批内分布（唯一的去重要求）

跨批次可以重复——数据好的标题就该反复用。但**同一批之内条条同构是硬伤**：用户挑不出东西，一眼就看出是套模板灌的。达标线（按 20 条基准，其他条数按比例缩放）：

- **同一句式骨架 ≤ 1 条**——这条最硬。"XX问了我三次"和"XX追问了我两天"算**同骨架**（结构相同、只换了槽内容），只能留一条。骨架怎么判见 toolkit 末节。
- **同一钩子类型 ≤ 2 条**（50 条这种大批量放宽到 ≤4 条，但骨架仍须条条不同）。
- 覆盖 **≥ 8 个不同钩子类型**（10 条时 ≥6 个）。
- 人群至少覆盖 3 类（如学生党 / 打工人 / 送礼人）。
- 搜索型占 25–35%，关键词分散，不重复堆在同一个词上。

用户指定只出某一类钩子（"都用社交证明那种"）时，钩子分布规则让位于用户要求，但**句式骨架仍必须条条不同**。

**一个例外要注意**：用户要把几批标题**合并成一份总表**的时候，"一批"的边界就变成了合并后的整个池子——总表里两条骨架相同的标题挨在一起，用户挑的时候等于只有一条可用。所以出新批次前先把要合并进去的历史条目过一遍，骨架、场景、人物锚点都要避开，不能只避开本批。
